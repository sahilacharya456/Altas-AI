## Remaining Risks

- `backend/api_legacy` still exists and still contains server-side AI integrations. It is now documented as legacy/admin-experimental, but future work should avoid new mobile dependencies on it.
- `apps/mobile/src/services/api_legacy/*` still exists for legacy reference. It is not currently imported by app screens after this phase, but should be archived or removed after migration confidence is high.
- Firestore rules still do not cover every security service write path identified in Phase 0.
- Some `.env.example` files necessarily contain secret variable names as placeholders. They do not contain real secret values.
- Android native builds now require restoring local ignored `apps/mobile/google-services.json` from Firebase Console.
- App Check is still not configured.
- Several large screens still need decomposition and consistent loading/empty/error state adoption.

## Phase 2 Recommendations

1. Harden Firestore rules for health, digital usage, budgets, analytics, profile, and all security write paths.
2. Add Firebase emulator tests for security collections and AI server-written collections.
3. Archive or remove unused mobile `services/api_legacy` once confirmed no flows import it.
4. Add App Check for production Firebase clients.
5. Move more analytics and intervention calculations server-side.
6. Apply `StateView` and shared route constants across remaining screens.
7. Add a privacy/data-retention model for conversations, AI feedback, parse errors, and security scans.
